# API Documentation

Base URL: `http://localhost:8000`. All bodies are JSON. The interactive OpenAPI
docs are served at `/docs` (Swagger) and `/redoc`, and the raw spec at `/openapi.json`.

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/accounts` | Create an account |
| `GET` | `/accounts/{account_id}` | Get an account |
| `GET` | `/accounts/{account_id}/balance` | Get current balance |
| `POST` | `/accounts/{account_id}/transactions` | Add a credit/debit transaction |
| `GET` | `/accounts/{account_id}/transactions` | Transaction history (filter, paginate, latest first) |
| `POST` | `/transfers` | Transfer money between two accounts (bonus) |
| `GET` | `/health` | Liveness check |

There are no update or delete endpoints for transactions or transfers. They are
immutable, and `PUT`/`PATCH`/`DELETE` return `405`.

---

## Error format

Every error, whether validation, business rule or not-found, uses the same shape:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance for this debit.",
    "details": { "account_id": "…", "balance": 100.0, "requested": 150.0 }
  }
}
```

For validation errors, `details` is a list of `{ "field", "message" }`.

| HTTP | `code` | When |
| --- | --- | --- |
| 400 | `INVALID_REQUEST_BODY` | Body is not valid JSON, or not a JSON object |
| 404 | `ACCOUNT_NOT_FOUND` | Account ID does not exist |
| 404 | `NOT_FOUND` | Unknown route |
| 405 | `METHOD_NOT_ALLOWED` | e.g. `DELETE` on transactions. The `Allow` header lists the supported methods |
| 409 | `DUPLICATE_TRANSACTION` | `reference_id` already used on this account |
| 409 | `DUPLICATE_TRANSFER` | Transfer `reference_id` already used from this source account |
| 422 | `INSUFFICIENT_BALANCE` | Debit/transfer larger than the balance |
| 422 | `BALANCE_LIMIT_EXCEEDED` | Credit would push the balance past the int64 storage limit |
| 422 | `INVALID_TRANSACTION_TYPE` | `type` missing or not `credit`/`debit` |
| 422 | `INVALID_AMOUNT` | Amount missing, ≤ 0, non-numeric, or more than 2 decimals |
| 422 | `INVALID_PAGINATION` | `page < 1`, `limit` outside 1–100, or non-integer |
| 422 | `VALIDATION_ERROR` | Any other invalid field (missing `name`/`reference_id`, unknown fields such as `balance`, a `reference_id` starting with the reserved `transfer:` prefix, …), or errors on several different fields at once |
| 500 | `INTERNAL_ERROR` | Unexpected failure; nothing partial is persisted |
| 503 | `SERVICE_BUSY` | Write lock not acquired within 5 s. Nothing was written. Retry after `Retry-After` seconds |

## `POST /accounts`

Creates an account. The balance always starts at `0`. `id` and `created_at` are
generated by the server. Sending `balance`, `id`, or any other unknown field
returns `422`.

**Request**

```json
{ "name": "Asha Verma" }
```

**201 Created**

```json
{
  "id": "f57dcc8e-3140-47ea-92e4-31e9c3110174",
  "name": "Asha Verma",
  "balance": 0.0,
  "created_at": "2026-10-28T07:13:55.310537+00:00"
}
```

Errors: `422 VALIDATION_ERROR` (missing/blank name, extra fields), `400 INVALID_REQUEST_BODY`.

---

## `GET /accounts/{account_id}`

**200 OK**: same shape as above. **404** `ACCOUNT_NOT_FOUND`.

## `GET /accounts/{account_id}/balance`

**200 OK**

```json
{ "account_id": "f57dcc8e-3140-47ea-92e4-31e9c3110174", "balance": 120.0 }
```

**404** `ACCOUNT_NOT_FOUND`.

## `POST /accounts/{account_id}/transactions`

Adds a transaction and updates the balance in one atomic operation.

| Field | Type | Rules |
| --- | --- | --- |
| `type` | string | required, `credit` or `debit` |
| `amount` | number or numeric string | required, `> 0`, at most 2 decimal places, no `_` digit separators (`"1_000"` is rejected) |
| `reference_id` | string | required, non-blank, ≤ 100 chars, unique per account |
| `description` | string | optional, ≤ 500 chars |

**Request**

```json
{ "type": "debit", "amount": 30, "reference_id": "INV-1002", "description": "Card payment" }
```

**201 Created**

```json
{
  "id": "2afb13eb-b5af-4dd1-bcbe-3c3902d652df",
  "account_id": "f57dcc8e-3140-47ea-92e4-31e9c3110174",
  "type": "debit",
  "amount": 30.0,
  "description": "Card payment",
  "reference_id": "INV-1002",
  "transfer_id": null,
  "created_at": "2026-10-28T07:13:55.466280+00:00"
}
```

**409 Duplicate.** No new row is written and the balance is unchanged. The original transaction is returned:

```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "A transaction with reference_id 'INV-1002' already exists for this account.",
    "details": { "existing_transaction": { "id": "2afb13eb-…", "amount": 30.0, "…": "…" } }
  }
}
```

**422 Insufficient balance.** No row is written and the balance is unchanged:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance for this debit.",
    "details": { "account_id": "f57d…", "balance": 100.0, "requested": 150.0 }
  }
}
```

Checks run in this order: account exists (404), then duplicate (409), then
sufficient balance (422).

## `GET /accounts/{account_id}/transactions`

Returns transactions latest first, by `created_at` descending.

| Query param | Default | Rules |
| --- | --- | --- |
| `type` | (both) | `credit` or `debit` |
| `page` | `1` | integer ≥ 1 |
| `limit` | `20` | integer 1–100 |

`GET /accounts/{id}/transactions?type=debit&page=1&limit=2`

**200 OK**

```json
{
  "data": [
    {
      "id": "2afb13eb-…",
      "account_id": "f57dcc8e-…",
      "type": "debit",
      "amount": 30.0,
      "description": null,
      "reference_id": "d2",
      "transfer_id": null,
      "created_at": "2026-10-28T07:13:55.466280+00:00"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 2,
    "total_records": 3,
    "total_pages": 2,
    "has_next": true,
    "has_prev": false
  }
}
```

A page past the end returns `"data": []` with correct metadata.
Errors: **404** `ACCOUNT_NOT_FOUND`, **422** `INVALID_PAGINATION` / `INVALID_TRANSACTION_TYPE`.

## `POST /transfers` (bonus)

Moves money atomically. It creates one transfer record, a **debit** on the source
and a **credit** on the destination, and updates both balances. All of it commits
or none of it does.

| Field | Type | Rules |
| --- | --- | --- |
| `from_account_id` | string | required, must exist |
| `to_account_id` | string | required, must exist, ≠ `from_account_id` |
| `amount` | number | required, `> 0`, at most 2 decimals |
| `reference_id` | string | required, unique per source account (idempotency key) |
| `description` | string | optional |

**Request**

```json
{ "from_account_id": "A…", "to_account_id": "B…", "amount": 30, "reference_id": "TRF-2001" }
```

**201 Created**

```json
{
  "id": "9c1e…",
  "from_account_id": "A…",
  "to_account_id": "B…",
  "amount": 30.0,
  "reference_id": "TRF-2001",
  "description": null,
  "created_at": "2026-10-28T07:20:01.002113+00:00",
  "debit_transaction_id": "e01b…",
  "credit_transaction_id": "77fa…"
}
```

Both legs show up in each account's history with `transfer_id` set.

Errors: **404** `ACCOUNT_NOT_FOUND` (either side), **409** `DUPLICATE_TRANSFER`,
**422** `INSUFFICIENT_BALANCE`, `INVALID_AMOUNT`, `VALIDATION_ERROR` (same account on both sides).
